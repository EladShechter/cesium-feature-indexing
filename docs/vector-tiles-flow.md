# Vector tiles flow — status and known issues

The vector tiles flow (lines + polygons simplified by `geojson-vt` in the worker, drawn by
`VectorLayerRenderer`) is currently **disabled**. `main.ts` runs the point clustering flow
(`TileRenderer`). To re-enable it, swap the commented lines in `main.ts` marked `Vector tiles flow`.

## Flow

1. `main.ts` builds random LineString/Polygon features and calls `client.buildVectorTiles(featureCollection)`.
2. `cluster-worker.ts` builds a `geojson-vt` index and replies `built`.
3. On camera change, `VectorLayerRenderer.requestRenderByBboxAndZoom` computes covering tiles
   (`tile-utils.getTilesInBbox`) and calls `client.getVectorTile(z, x, y)` for tiles not already drawn.
4. The worker converts the tile's features from tile-pixel coordinates back to lon/lat GeoJSON
   (`toGeoJsonFeatures`) and replies `vectorTile`.
5. The renderer creates one Cesium `Entity` per feature in a `CustomDataSource`.

## Already fixed

- `randomPolygon` threw on startup: turf's default `max_radial_length` (10°) is bigger than the bbox.
- `requestRenderByBboxAndZoom` always returned early because `this.data` was never set.
- The worker sent raw geojson-vt features (numeric `type`, tile-pixel coordinates). The renderer
  could not read them, so the entities had no geometry.
- `entities.add()` threw when a feature crossing a tile border showed up in two tiles with the same id.
  Entity ids are now generated by Cesium, and the source id is kept in `properties.featureId`.
- Polygon/polyline positions used `CallbackProperty(..., false)`, which recalculates every frame.
  They are now constant values.
- `PointGraphics.color` / `outlineColor` were given a `ColorMaterialProperty` instead of a `Color`.
- A race on `vectorLayersDS`, which was assigned in a `.then()` and could be undefined in `clearTiles()`.

## Known issues (not fixed yet)

### 1. Entity API does not scale
Each feature is a separate `Entity` with clamp-to-ground geometry. Cesium builds ground geometry
asynchronously per entity, so thousands of entities per view are slow to appear and heavy on memory.
**Direction:** batch each tile into one `GroundPrimitive` (polygons) / `GroundPolylinePrimitive` (lines)
with many `GeometryInstance`s, and use per-instance attributes for color and picking ids.

### 2. Features crossing tile borders are drawn once per tile
geojson-vt clips each feature to every tile it touches, plus a `buffer` (64 px). A feature crossing
borders is drawn as several overlapping pieces. With translucent fills the overlap in the buffer area
looks darker, and picking returns several entities for one feature.
**Direction:** use `buffer: 0` for polygon fills (accepting possible seams), or merge the pieces by
`featureId` on the main thread.

### 3. MultiPolygons are not supported in the conversion
`toGeoJsonFeatures` treats the first ring of a type-3 tile feature as the outer ring and all the other
rings as holes. geojson-vt flattens MultiPolygons into one ring list, where outer rings and holes are
told apart by winding order. **Direction:** split rings by signed area (winding) into separate polygons.

### 4. The tile "cache" is not a cache
`tileCache` entries are deleted as soon as a tile leaves the view (`cleanupOldTiles`), and the LRU
`timestamp` is never read. Panning back always re-requests and re-creates the entities.
**Direction:** keep off-screen tiles hidden (`entity.show = false`, or remove the primitive from the scene)
and evict by LRU size limit.

### 5. Zoom changes cause a blank flash
All tiles from the previous zoom are removed immediately, before the new zoom's tiles arrive.
**Direction:** keep the previous tiles until every covering tile at the new zoom is ready, the way
`TileRenderer` (cluster flow) already does with `staleTiles`.

### 6. Polygon outlines are ignored
`outline` / `outlineWidth` are not supported on terrain-clamped polygons (Cesium logs a warning),
and `outlineWidth > 1` is not supported on most WebGL implementations. **Direction:** draw outlines
as a separate clamped polyline (`GroundPolylinePrimitive`) when they are needed.

### 7. `getTilesInBbox` does not handle the antimeridian
In `tile-utils.ts`, when the view crosses the antimeridian (west > east), the min/max range covers
the wrong side of the world. `TileRenderer.computeCoveringTiles` already handles this correctly.
The two should be merged into one helper.

### 8. Style is not configurable
`setStyle` / `setZoomRange` are commented out, so `style` is always the defaults (white fill, black stroke)
and `opacity` is unused.

### 9. Tilted views request too many tiles
`computeViewRectangle` on a tilted camera that shows the horizon returns a huge bbox, while the zoom is
calculated from the view width. The result can be hundreds of tiles at high zoom. This applies to the
cluster flow too. **Direction:** cap the tile count (reduce zoom until it fits) or select tiles by
screen-space error, the way Cesium's imagery layers do.
